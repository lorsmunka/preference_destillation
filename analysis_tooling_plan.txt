ANALYSIS TOOLING PLAN
=====================

Created: 2026-04-04
Purpose: Tools for comparing runs, graphing metrics, and generating
         thesis-quality visualizations from training log data.


=== WHAT EXISTS NOW ===

Current analysis tools (in analysis/):
  - visualize_logs.py: Single-run plotting (loss, accuracy, LR, KL ratio,
    temperature, confusion matrices, mini-eval). Saves training_progress.png.
  - training_analysis.py: TrainingAnalyzer class, per-run summary + matplotlib plots.
  - evaluate_model.py: Load checkpoint, run inference, get accuracy metrics.
  - inference.py: Interactive inference, list runs, load checkpoints.
  - generation_analysis.py: Data generation stats.

Gap: Everything is single-run. There is no way to compare multiple runs
side by side, overlay curves, or produce scaling/ablation charts.


=== TOOL 1: RUN COMPARATOR (terminal text output) ===

File: analysis/compare_runs.py
Purpose: Quick terminal comparison of N selected runs across key metrics.

Usage:
  python -m analysis.compare_runs                       # interactive picker
  python -m analysis.compare_runs run1 run2 run3        # by name
  python -m analysis.compare_runs --all                 # all completed runs
  python -m analysis.compare_runs --prefix tsc-scale    # filter by prefix

Output (example):
  +---------------------------------+----------+----------+----------+
  | Metric                          | scale-20 | scale-40 | scale-64 |
  +---------------------------------+----------+----------+----------+
  | Parameters                      | 5.0M     | 10.0M    | 17.0M    |
  | Hidden dim                      | 20       | 40       | 64       |
  | Layers                          | 2        | 2        | 2        |
  | Heads                           | 1        | 1        | 1        |
  | Input vocab                     | 262,144  | 262,144  | 262,144  |
  | Training time (hours)           | 1.2      | 2.4      | 4.1      |
  | Final train loss                | 1.234    | 0.987    | 0.654    |
  | Final eval loss                 | 1.345    | 1.012    | 0.701    |
  | Teacher-forced accuracy (final) | 72.3%    | 81.5%    | 89.2%    |
  | Student accuracy (final)        | 58.1%    | 69.4%    | 78.7%    |
  | Classification accuracy (final) | 45.2%    | 62.1%    | 74.3%    |
  | Convergence batch (>90% TF)     | never    | 4200     | 1800     |
  +---------------------------------+----------+----------+----------+

Data sources:
  - runs/{name}/info.json for config + timestamps
  - runs/{name}/logs/training.jsonl for batch-level metrics
  - runs/{name}/logs/eval_epoch.jsonl for epoch-level eval results
  - runs/{name}/logs/mini_eval.jsonl for mid-training eval snapshots

Features:
  - Sort runs by any column (--sort-by student_accuracy)
  - Show delta vs best run (highlight winner per metric)
  - Export to CSV (--csv output.csv) for spreadsheet work
  - Show per-epoch breakdown (--epochs) or just final (default)


=== TOOL 2: MULTI-RUN GRAPH BUILDER (matplotlib) ===

File: analysis/compare_plots.py
Purpose: Overlay training curves from multiple runs on the same axes.
         For thesis figures and experiment analysis.

Usage:
  python -m analysis.compare_plots run1 run2 run3       # by name
  python -m analysis.compare_plots --prefix tsc-scale    # filter by prefix
  python -m analysis.compare_plots --all --sort params   # all, ordered by size

Chart types (each as a subplot or standalone with --chart flag):

  1. ACCURACY vs PARAMS (scaling curve)
     X: parameter count (log scale)
     Y: final student accuracy, teacher-forced accuracy, classification accuracy
     Style: line + markers, one point per run
     This is THE thesis chart for the scaling experiment.

  2. ACCURACY OVER TRAINING (overlay)
     X: batch number (or training step)
     Y: accuracy (teacher-forced or student)
     One curve per run, color-coded, legend shows run name + params
     Good for seeing convergence speed differences.

  3. LOSS OVER TRAINING (overlay)
     X: batch number
     Y: loss (combined, KL, or CE selectable)
     One curve per run.

  4. EPOCH EVAL COMPARISON (grouped bar chart)
     X: run names
     Y: teacher-forced / student / classification accuracy (grouped bars)
     Clear visual comparison of final performance.

  5. TRAINING EFFICIENCY
     X: wall-clock time (hours)
     Y: student accuracy
     Shows which config reaches target accuracy fastest.

  6. REDUCED vs FULL VOCAB COMPARISON
     Paired bar chart: for each param budget (5M, 10M, 36M), show
     full-vocab run vs reduced-vocab run side by side.

  7. ANNEALING COMPARISON
     X: batch number
     Y: student accuracy (overlay)
     Runs: temp-anneal-3to1, temp-anneal-5to1, kl-anneal-0.99to0.4, kl-anneal-0.9to0.1
     Shows which annealing strategy converges best.

  8. MINI-EVAL TRAJECTORY (overlay)
     X: mini-eval index (or batch number)
     Y: student accuracy from mini-evals
     Higher resolution than epoch evals, shows mid-training dynamics.

Output:
  - Saves to analysis/comparison_plots/ directory
  - Each chart type saved as separate PNG (thesis-ready, 300 dpi)
  - Combined dashboard PNG with all charts (for quick overview)
  - --show flag to display interactively

Style:
  - Clean, publication-ready (no chartjunk)
  - Consistent color palette across all charts
  - Run names abbreviated in legend (strip common prefix)
  - Parameter counts in legend where relevant
  - Grid lines, axis labels, titles


=== TOOL 3: SCALING CURVE ANALYZER ===

File: analysis/scaling_analysis.py
Purpose: Dedicated tool for the scaling experiment — finds the knee,
         fits curves, extrapolates.

Features:
  - Plots accuracy vs params with fitted curve (power law or log)
  - Marks the "knee" (diminishing returns point)
  - Shows accuracy gain per additional million parameters
  - Extrapolates: predicted accuracy at 200M, 500M params
  - Compares reduced-input-vocab runs against the scaling curve
    (do they sit above or below the full-vocab curve?)

Output:
  - scaling_curve.png (the main thesis figure)
  - Terminal summary: "Knee at ~X params, Y% accuracy.
    Doubling from here gains only Z% more."

=== DATA FORMAT REFERENCE ===

All data lives in runs/{run_name}/logs/:

training.jsonl (per batch):
  {"type": "train_batch", "epoch": 1, "batch": 42, "loss": 1.23,
   "kl_loss": 0.8, "ce_loss": 0.43, "accuracy": 0.75,
   "learning_rate": 5.2e-4, "kl_ratio": 0.85, "temperature": 2.8,
   "steps": 32, "time_seconds": 1.4, "session_id": "..."}

eval_epoch.jsonl (per epoch):
  {"type": "eval_epoch", "epoch": 1, "avg_loss": 0.98,
   "teacher_forced_accuracy": 0.89, "student_accuracy": 0.72,
   "classification_accuracy": 0.65, "confusion_matrices": {...}}

mini_eval.jsonl (mid-epoch):
  {"type": "mini_eval", "batch": 1000,
   "teacher_forced_accuracy": 0.85, "student_accuracy": 0.68,
   "classification_accuracy": 0.61}

info.json (run config + status):
  {"run_name": "...", "domain": "...", "hidden_dim": 128, "num_layers": 4,
   "num_heads": 2, "status": "completed", "started_at": "...",
   "completed_at": "...", "model_info": {"total_parameters": 9800000, ...}}
