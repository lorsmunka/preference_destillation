PREZENTÁCIÓ KÉSZÍTÉSI PROMPT — TDK ELŐADÁS
=============================================

Te egy prezentáció tervező AI vagy. A feladatod egy ~30 perces TDK (Tudományos Diákköri Konferencia) előadás slide-jainak elkészítése. Az előadás nyelve MAGYAR. Az alábbiakban megkapod a projekt teljes leírását, az elvárt struktúrát, stílust és minden szükséges adatot.

================================================================
1. KONTEXTUS ÉS CÉL
================================================================

A projekt egy egyetemi szakdolgozat proof-of-concept-je:
- Nagy nyelvi modell (Gemma 3 4B) domain-specifikus tudásának desztillálása kisebb transformer modellekbe
- Csökkentett kimeneti szótárral (262,144 → 525 token, 99.8%-os redukció)
- Két domain: Reddit komment klasszifikáció (tone, sentiment, safety, toxicity → JSON) és matematikai szöveges feladatok
- A cél bizonyítani, hogy a technika működik autoregresszív generálásra is, nem csak klasszifikációra

A TDK közönség: egyetemi oktatók, PhD hallgatók, BSc/MSc hallgatók. A zsűri értékeli a tudományos igényességet, de a közönség vegyes szintű. Az előadás legyen érthetően felépített, vizuálisan vonzó, és mutassa be a projekt újszerűségét.

--- BEVEZETŐ BLOKK (5-6 slide, ~5 perc) ---

SLIDE 1: Címlap
- Cím: "Domain Specifikus LLM Desztillációs Pipeline"
- Alcím: "Hogyan taníthatunk kis modelleket nagy modellek tudására?"
- Név, egyetem, szak, konzulens, dátum (ezeket [NÉV], [EGYETEM], [SZAK], [KONZULENS] placeholderekkel jelöld)
- TDK logó placeholder

SLIDE 2: Motiváció — Miért érdekes ez?
- Az LLM-ek (ChatGPT, Gemini, Claude) fantasztikusan okosak, DE:
  - Drágák (API költség per hívás)
  - Lassúak (válaszidő)
  - Nem futtathatók lokálisan (telefonon, edge eszközön)
- Sok feladathoz túlzás egy 100+ milliárd paraméteres modell
- Példa: egy egyszerű sentiment klasszifikáció nem igényli a teljes GPT-4 kapacitását
- Kérdés: Mi lenne, ha a nagy modell "megtanítaná" egy kisebb modellt az adott feladatra?

SLIDE 3: Mi a Knowledge Distillation?
- Hinton et al. (2015) — "Distilling the Knowledge in a Neural Network"
- Teacher-Student paradigma ábra:
  ┌─────────────┐         ┌─────────────┐
  │  TEACHER     │  tudás  │   STUDENT   │
  │  Gemma 3 4B  │ ──────→ │  Kis modell │
  │  4.3B param  │         │  5M-198M    │
  └─────────────┘         └─────────────┘
- A "dark knowledge" fogalma: nem csak a helyes választ adjuk át, hanem a teacher modell bizonytalanságait, preferenciáit is
- Soft targets vs Hard targets: a teacher outputja gazdagabb információt hordoz, mint egy egyszerű címke
- Példa: ha a teacher 70% "negative", 25% "neutral", 5% "positive"-ot mond → ez sokkal több info, mint egyszerűen "negative"

SLIDE 4: A feladat — Reddit komment klasszifikáció
- Bemenet: egy Reddit komment (3-25 token)
- Kimenet: strukturált JSON, 4 kategória:
  - tone: aggressive / rude / neutral / polite / friendly
  - sentiment: negative / neutral / positive
  - safety: harmful / safe
  - toxicity: toxic / respectful
- Élő példa:
  Bemenet: "F**k you and your family"
  Kimenet:
  ```json
  {
    "tone": "aggressive",
    "sentiment": "negative",
    "safety": "harmful",
    "toxicity": "toxic"
  }
  ```
- Miért autoregresszív generálás klasszifikáció helyett? → Mert a cél bizonyítani, hogy a desztilláció generatív feladatra is működik, nem csak egyszerű címkézésre

SLIDE 5: A projekt áttekintése (Overview ábra)
- Vizuális pipeline ábra:
  Reddit kommentek → [Gemma 3 4B Teacher] → Logitok + JSON → [Tanítás KL+CE loss] → [Student Transformer] → JSON output
- 3 fázis: Adatgenerálás → Tanítás → Kiértékelés
- Megemlíteni: a kód moduláris, könnyen adaptálható más feladatokra (matek, email, moderáció)

--- TECHNIKAI BLOKK (10-12 slide, ~12 perc) ---

SLIDE 6: Kimeneti szótár redukció — A projekt fő innovációja
- Ez a legfontosabb technikai hozzájárulás!
- Gemma teljes szótára: 262,144 token
- A feladathoz szükséges tokenek: mindössze 27 (JSON struktúra + kategória értékek)
- Kiegészítő tokenek (dark knowledge-hez): +498 token
- Összesen: 525 token → 99.8%-os redukció
- Ábra: a szótár felépítése rétegekre bontva:
  ┌──────────────────────────────┐
  │ Kiegészítő tokenek (~450)    │ ← "dark knowledge" hordozók
  │ Prompt tokenek (~25)         │ ← kiértékelési utasítás szavai
  │ Whitespace tokenek (~20)     │ ← formázás
  │ Szükséges tokenek (27)       │ ← JSON struktúra + értékek
  └──────────────────────────────┘
- Miért nem 27? → A 498 kiegészítő token segít a teacher "gondolkodásmódjának" átadásában (soft targets gazdagabb info)
- De: 525 vs 262,144 → a kimeneti projekció paraméterei 99.8%-kal csökkennek

SLIDE 7: A Student modell architektúrája
- Decoder-only Transformer (mint a GPT, Gemma, Claude)
- Fő komponensek:
  - Input embedding: teljes Gemma vocab (262,144 token) — a student bármilyen szöveget megért
  - Transformer blokkok: Multi-head Attention + Feed-forward (GeGLU)
  - Output projekció: CSAK 525 tokenre → itt történik a drámai méretcsökkenés
- Modern elemek (mint a Gemma-ban):
  - RMSNorm (gyorsabb, mint LayerNorm)
  - RoPE (Rotary Position Embedding — paramétermentes pozíciókódolás)
  - GeGLU aktiváció (gated feed-forward)
- Egyszerű ábra a modell architektúráról:
  Input tokenek → [Embedding 262K] → [Transformer ×N] → [Output Proj 525] → Predikció

SLIDE 8: Tanítási stratégia — Curriculum Learning
- A tanítás két veszteségfüggvényt kombinál változó arányban:
  1. KL divergencia: "Gondolkodj úgy, mint a teacher" (eloszlás-illeszkedés)
  2. Cross-Entropy: "Add meg a helyes választ" (token-predikció)
- Arányváltozás cosine annealing-gel:
  - Tanítás eleje: 99% KL + 1% CE → "Először tanuld meg a teacher gondolkodásmódját"
  - Tanítás vége: 30% KL + 70% CE → "Most koncentrálj a helyes válaszra"
- Ábra: a KL/CE arány cosine görbéje az idő függvényében
- Ez a megközelítés a Curriculum Temperature (Li et al., 2023) és az Annealing KD (Jafari et al., 2021) munkákkal konzisztens
- Distillation temperature: T=3.0 (a teacher logitjait "lágyítja", több információt ad át)

SLIDE 9: Tanítás vizualizáció
- A pilot run tanítási görbéi (ha van ábra, vagy leírás alapján rajzolj):
  - Loss görbe: éles csökkenés az első batcheknél (~25 → ~2), majd lassú konvergencia
  - Accuracy görbe: 35% → 95%+ (teacher-forced)
  - KL/CE arány változása időben
  - Learning rate cosine görbe (warmup + decay)
- 3 epoch, ~100 batch, 3232 mondat a pilot tesztben
- A fluktuáció oka: a CE loss nagyobb súlyt kap idővel → élesebb gradiens

SLIDE 10: Kiértékelés — Hogyan mérjük a sikert?
- Háromféle pontosság:
  1. Teacher-forced accuracy (~98%): a modell mindig a helyes kontextust kapja → optimista becslés
  2. Student accuracy (~88%): a modell saját predikcióit használja → realisztikus
  3. Klasszifikációs pontosság: a JSON-ból kinyert kategória értékek egyezése a teacher-rel
- Confusion mátrixok kategóriánként (tone, sentiment, safety, toxicity)
- Fontos: a student maximum annyira lehet jó, mint a teacher! A teacher hibáit is megtanulja.
- Vizuális példa jó és rossz predikcióval:

  HELYES (100%):
  Input: "F**k you and your family"
  → aggressive, negative, harmful, toxic ✓

  HIBÁS (69%):
  Input: "Bro no way you did this to me again"
  Student: neutral, neutral, safe, respectful ✗
  Teacher: aggressive, negative, harmful, toxic
  (Megjegyzés: a teacher klasszifikációja is vitatható!)

SLIDE 11: Skálázási kísérlet — Mennyi paraméter kell?
- A központi kérdés: mekkora student modell szükséges a feladathoz?
- 8 modellméret szisztematikus vizsgálata:

  | Modell          | Hidden | Layers | Heads | ~Paraméter |
  |-----------------|--------|--------|-------|------------|
  | tsc-scale-5M    | 20     | 2      | 1     | 5.2M       |
  | tsc-scale-10M   | 40     | 2      | 1     | 10.5M      |
  | tsc-scale-17M   | 64     | 2      | 1     | 17.0M      |
  | tsc-scale-36M   | 128    | 4      | 2     | 36.2M      |
  | tsc-scale-53M   | 192    | 6      | 3     | 53.6M      |
  | tsc-scale-74M   | 256    | 8      | 4     | 75.6M      |
  | tsc-scale-127M  | 384    | 12     | 6     | 127.8M     |
  | tsc-scale-198M  | 512    | 16     | 8     | 198.9M     |

- Azonos hiperparaméterek (LR, batch, temp, KL arány) — csak a méret változik
- Cél: megtalálni a "térdet" a pontosság-paraméterszám görbén

SLIDE 12: Embedding dominancia — Kis modellek érdekes problémája
- Az input embedding (262,144 token) fix méretű, nem függ a modell kapacitásától
- Kis modelleknél az embedding uralja a paraméterszámot:

  | Modell | Embedding % | Transformer % |
  |--------|-------------|---------------|
  | 5M     | 94%         | 6%            |
  | 36M    | 76%         | 24%           |
  | 74M    | 59%         | 41%           |
  | 198M   | 33%         | 67%           |

- Az 5M-es modellnél a paraméterek 94%-a az embeddingben van — a tényleges "gondolkodó" rész csak 6%!
- Jövőbeli optimalizáció: input vocab csökkentése is (262K → ~40K → 85% embedding megtakarítás)
- De: a használaton kívüli embeddingeknél amúgy sem frissül a gradiens → a tényleges számítási költség már most is alacsonyabb

SLIDE 13: Jelenlegi eredmények
- A 74M-es modell (256 hidden, 8 layer) tanítás közben:
  - Loss: 43.39 → 0.36 (99%+ csökkenés az első epoch alatt)
  - Token-szintű pontosság: 20% → 98%+ (teacher-forced)
  - Sebesség: ~2.2 másodperc / batch (32 példa)
- A pilot teszt (537M modell, 100 batch, 3 epoch):
  - Teacher-forced accuracy: ~98.97%
  - Student accuracy: ~87.69%
  - Valid JSON generálás az esetek túlnyomó többségében
- A modell megtanulta a JSON struktúrát stabilan generálni
- A bizonytalanság a kategória értékeknél jelentkezik (aggressive vs neutral, stb.)

TARTALÉK SLIDE A: Irodalmi háttér részletek
- Hinton (2015) — Knowledge Distillation alapmű
- DistilBERT (2019) — 40% kisebb, 97% teljesítmény
- TinyBERT (2019) — 7.5x kisebb, 9.4x gyorsabb, 96.8% GLUE
- MiniLLM (2023) — Reverse KL autoregresszív modellekhez
- Kolesnikova (2022) — Vocabulary reduction distillation

TARTALÉK SLIDE B: Loss függvény matematikai részletek
- L_total = KL_ratio × L_KL + (1 - KL_ratio) × L_CE
- L_KL = KL_div(softmax(student_logits/T), softmax(teacher_logits/T)) × T²
- L_CE = CrossEntropy(student_logits/T, target_index) × T²
- T = desztillációs hőmérséklet (3.0)
- KL_ratio: 0.99 → 0.3 cosine annealing

TARTALÉK SLIDE C: Részletes architektúra összehasonlítás
- Teacher (Gemma 3 4B): 4.3B param, 2048 hidden, 26 layers
- Student (pilot): 537M param, 1024 hidden, 16 layers (~8x kisebb)
- Student (skálázás): 5M-198M, 20-512 hidden, 2-16 layers
- Paraméterszám képlet: 262,144 × h + 16 × L × h²

TARTALÉK SLIDE D: Encoding bug történet
- 97 órás tanítás, loss csökken, teacher-forced acc 80-90%, DE student acc csak 10-20%
- Generált JSON-ok hibásak voltak
- Ok: encoding hiba néhány tokennél (pl. "_\"" rosszul kódolva)
- Tanulság: a két accuracy típus összehasonlítása nélkül nem derült volna ki
- (A zsűri szereti az őszinte debugging narratívákat)

TARTALÉK SLIDE E: Matek domain részletek
- 260+ sablon, 13 művelettípus
- Szemantikus változók (nevek, helyek, tárgyak)
- Csak 31 token szükséges az output szótárhoz
