Preference Distillation

Distilling Gemma 3 4B into a from-scratch transformer over a reduced vocabulary · codebase reference

What the codebase does

A teacher model answers a narrow task; its full output distribution is stored at every generated token. A small transformer is then trained from random initialisation to reproduce those distributions over a reduced vocabulary of about 525 tokens.

pipeline
corpus.jsonl  →  generate_data.py  →  batches/   teacher answers + per-step logits
batches/      →  train.py          →  runs/      checkpoints, logs, info.json
runs/         →  analyze.py        →  tables     metrics read back from logs

Each stage writes files the next one reads, so any stage can be re-run alone. Completed jobs and runs are skipped, so every script is safe to run again.

repository
library/
  shared/     paths, reduced-vocabulary builder, metrics, logging
  domain/     one package per task + registry
  model/      Transformer, StudentModel
  data_gen/   teacher data generation
  training/   Trainer, TrainingRunner, BatchHandler
  tooling/    Analysis, Run / RunStore / Experiment, plots and tables
  specs.py    TrainingRun, GenerationJob

train.py  generate_data.py  analyze.py     entry scripts — edit the list at the top
experiments/   one script per named experiment
batches/       teacher data (JSONL)
runs/          per-run artifacts

Importing library does not import torch; that happens only when a model method runs.

Generating teacher data

A job names a domain and a size. Everything else has a default.

generate_data.py
from library import GenerationJob
from library.domain import REDDIT_SENTIMENT

JOBS = [
    GenerationJob(
        domain=REDDIT_SENTIMENT,
        max_examples=8000,
        batch_size=32,
        description="Sentiment distillation data",
    ),
]

python generate_data.py writes one JSONL file per batch. Each record holds the input text, the teacher's response, and the full logit vector at every generation step.

Output layout

on disk
batches/<domain>/<teacher_model>/
    info.json          status, so completed jobs are skipped
    batch_0001.jsonl   text · teacher response · logits per step
    batch_0002.jsonl

The teacher name is part of the path, so data from different teachers never mixes. Press % (or Ctrl+C headless) to stop cleanly and keep what has been written.

Configuring a domain

A domain is one self-contained package holding the teacher prompt, the stop rule, the scoring metric, the structural check, and the domain's slice of the reduced vocabulary.

library/domain/<your_task>/__init__.py
class RedditSentimentDomain(Domain):
    name = "reddit_comment_sentiment"
    stop_token = "}"
    max_steps = 50
    max_input_tokens = 25

    example_responses = [                 # seeds the hardest vocabulary section
        '```json\n{\n    "tone": "aggressive", "sentiment": "negative" ... }',
    ]
    prompt_tokens = ["Analyze", "sentence", "JSON", "tone", "sentiment"]

    def teacher_prompt(self, text: str) -> str:
        return f'Analyze this sentence and return your evaluation as JSON:\n\n{text}'

    def task_metric(self) -> ClassificationMetric:
        return ClassificationMetric()

    def structural_validity(self, output: str) -> bool:
        try:
            json.loads(output.replace("```json", "").replace("```", "").strip())
            return True
        except json.JSONDecodeError:
            return False

    def build_corpus(self, count=None) -> None:
        from .corpus import build_corpus
        build_corpus(self.corpus_path, count=count)

Four ordered sections. The domain owns two of them; the rest is shared.

The loss

KL pulls the student toward the teacher's whole distribution; cross-entropy pulls it toward the chosen token. The ratio and temperature interpolate from their _start to their _end value across training.

library/training/trainer.py
def _compute_loss(self, student_logits, teacher_logits, target_indices, reduction='mean'):
    temperature = self._get_current_temperature()
    student_log_probs = F.log_softmax(student_logits / temperature, dim=-1)
    teacher_probs = F.softmax(teacher_logits / temperature, dim=-1)

    kl_loss = F.kl_div(student_log_probs, teacher_probs,
                       reduction='batchmean') * (temperature ** 2)
    ce_loss = F.cross_entropy(student_logits / temperature,
                              target_indices, reduction=reduction) * (temperature ** 2)

    kl_ratio = self._get_current_kl_ratio()
    return kl_loss, ce_loss, kl_ratio * kl_loss + (1 - kl_ratio) * ce_loss

What a run produces

runs/<run_name>/
info.json          full config, status, model_info (confirmed vocabulary size)
logs/*.jsonl       per-batch and per-epoch records
checkpoints/*.pt   weights

Distribution metrics — teacher and student entropy, top-k accuracy, distribution overlap, mean target rank, perplexity, termination rate, length ratio — are computed during evaluation and written to the logs, so analysis never reloads the model.

analyze.py
from library import Analysis, RunStore

print(Analysis("sentiment-kl99to50").summary())
print(Analysis.compare([r.name for r in RunStore().completed()]).sort("params").table())

Creating an experiment

An experiment is one script: the runs it trains, and the analysis that reads them back. Completed runs are skipped, so it trains only what is missing and stays re-runnable.

experiments/vocab_rank_sweep.py
"""E1 — Does shrinking the output vocabulary relieve the output-rank bottleneck?

    python experiments/vocab_rank_sweep.py

5 vocabulary levels x 5 seeds = 25 runs, ~3 min each. Completed runs are skipped.
"""

from _common import seeded_run_training, write_rows, best_and_final

from library import Analysis, TrainingRun
from library.domain import REDDIT_SENTIMENT

EXPERIMENT = "ideaA-vocab-rank-sweep"

AUXILIARY_LEVELS = [(0.0, 64), (0.1, 113), (0.25, 193), (0.5, 300), (1.0, 525)]
SEEDS = [1, 2, 3, 4, 5]

MATCHED_BODY = dict(                      # held fixed across the sweep
    domain=REDDIT_SENTIMENT,
    hidden_dim=48, num_layers=3, num_heads=1, dropout=0.08,
    epoch_count=3, batch_size=32, learning_rate=0.0015,
    max_training_examples=8000,
)

runs = [
    (seed, TrainingRun(
        **MATCHED_BODY,
        run_name=f"vocab-{int(level * 100)}pct-s{seed}",
        experiment=EXPERIMENT,
        auxiliary_token_percentage=level,
        description=f"auxiliary {level}, expected V={expected_v}",
    ))
    for level, expected_v in AUXILIARY_LEVELS
    for seed in SEEDS
]

seeded_run_training(runs)                 # trains what is missing, seeds each replicate

Reading the cohort back

Runs sharing an experiment tag form a cohort, reported as mean ± std.

same file, below the runs
cohort = Analysis.experiment(EXPERIMENT)

rows = []
for level, expected_v in AUXILIARY_LEVELS:
    for seed in SEEDS:
        run = Analysis(f"vocab-{int(level * 100)}pct-s{seed}").run
        best, final = best_and_final(run)
        rows.append({
            "run": run.name,
            "auxiliary": level,
            "vocab_size": run.total_parameters,
            "task_accuracy_best": best.task_accuracy,
            "task_accuracy_final": final.task_accuracy,
            "teacher_entropy": final.teacher_entropy,
        })

write_rows("ideaA_vocab_sweep.csv",
           ["run", "auxiliary", "vocab_size",
            "task_accuracy_best", "task_accuracy_final", "teacher_entropy"],
           rows)

Substituting your own model

Three separate substitution points: the teacher, the student architecture, and the task.

1 · A different teacher

Any HuggingFace causal LM. It is loaded with AutoModelForCausalLM.from_pretrained and its tokenizer defines the input vocabulary the student is compressed against.

generate_data.py, then train.py
GenerationJob(domain=REDDIT_SENTIMENT, teacher_model="Qwen/Qwen2.5-1.5B-Instruct")

TrainingRun(domain=REDDIT_SENTIMENT, run_name="qwen-teacher",
            teacher_model="Qwen/Qwen2.5-1.5B-Instruct")

The teacher name is a path segment for batches/, the input vocabulary and the run, so two teachers never share data. Generate first, then train against those batches with the same teacher_model value.

2 · A different student architecture

Width, depth and heads are run parameters. Anything beyond that means constructing the model yourself — there is no model argument on TrainingRun.

library/model/transformer.py
Transformer(
    domain=REDDIT_SENTIMENT,          # Domain object or name
    teacher_model=DEFAULT_TEACHER_MODEL,
    hidden_dim=48,
    num_layers=3,
    num_heads=1,
    max_seq_length=None,              # defaults to domain.max_seq_length
    dropout=0.08,
    auxiliary_token_percentage=1.0,
    input_vocabulary=None,            # compact input-id mapping
)

Transformer is a plain nn.Module, built inside TrainingRunner.run() and handed to Trainer. To train a different architecture, construct it there and pass it in its place — the trainer only requires a module that maps remapped input ids to logits over the reduced output vocabulary.

library/training/training_runner.py — the substitution point
transformer = Transformer(
    domain=self.domain,
    teacher_model=self.teacher_model,
    hidden_dim=self.config["hidden_dim"],
    num_layers=self.config["num_layers"],
    num_heads=self.config["num_heads"],
    dropout=self.config["dropout"],
    auxiliary_token_percentage=self.config.get("auxiliary_token_percentage", 1.0),
    input_vocabulary=input_vocabulary,
)

trainer = Trainer(transformer, logger, self.exit_listener, batch_handler, trainer_config)

Your module must expose get_model_info() for info.json, and keep the same input-id remapping and output vocabulary so the stored teacher logits still line up.

3 · A different task

Subclass Domain and pass the object. No registration is needed to generate data or train; the registry only resolves names for steps that run in a separate process.

your script
from library.domain import Domain

class MyTaskDomain(Domain):
    name = "my_task"
    stop_token = ""
    max_steps = 40
    max_input_tokens = 30
    example_responses = ["..."]
    def teacher_prompt(self, text): return f"..."
    def task_metric(self): return MyMetric()

domain = MyTaskDomain()

GenerationJob(domain=domain, max_examples=4000)
TrainingRun(domain=domain, run_name="my-task-baseline")
Analysis("my-task-baseline").evaluate(domain=domain)
