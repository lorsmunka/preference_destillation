MATH TUTOR (math_tutor)                                   [SPEC 2026-10-04]

Agent = model + harness. The model is the distilled student; the harness
holds the conversation state (problem, earlier answers) and checks each
turn. This domain is the model's side: one turn in, one answer out.

ITEM (one json line, the unit everything else is built from)
  {
    "id":         "S05-mem-0042",
    "slice":      "S05",                     taxonomy cell, see SLICES
    "unknown":    "product",                 position of the unknown
    "grade":      3,                         2 | 3 | 4
    "distractor": "none",                    none | number | sentence | keyword
    "context":    "bakery",
    "source":     "memory",                  memory | online:<url>
    "problem":    "Mia bakes 4 trays of 6 muffins. How many muffins is that?",
    "solve":      "def solve():\n    trays = 4\n    per_tray = 6\n    muffins = trays * per_tray\n    return {'muffins': muffins, 'answer': muffins}",
    "follow_ups": [
      {"question": "She sells 9 of them. How many are left?",
       "solve": "def solve(state):\n    left = state['muffins'] - 9\n    return {**state, 'left': left, 'answer': left}"}
    ]
  }
  Answers are never written by the agent. The validator executes solve()
  and each follow-up's solve(state) on the previous turn's returned dict,
  and stores answer, shape and split next to the item.

VALIDATION (an item that fails any check is dropped, reason logged)
  - every function runs in a sandbox (no imports, no I/O, 1 s limit) and
    returns a dict with an integer "answer"
  - every intermediate and final value is an integer 0..999 (no negatives,
    no fractions; division must use // or %, and // must be exact unless
    the slice is S07, which is about remainders)
  - every numeric literal in a function appears in its text, as digits or
    as a number word (two, dozen, twice, half...); start-up range 0..99
  - the text's unused DIGIT numbers match the label: distractor "number"
    needs exactly one, every other label needs zero (number words in prose,
    "the two classes", are fine; changed after the pilot, where writers
    twisted sentences to avoid them)
  - 1 to 3 follow-ups optional; each must read state (no standalone question)

SLICES (10 cells, one writing agent pair each)
  S01 change, join        result | change | start unknown          G2
  S02 change, separate    result | change | start unknown          G2
  S03 combine             whole | part unknown                     G2
  S04 compare, additive   difference | larger | smaller unknown,   G2-3
                          consistent and inconsistent wording
  S05 equal groups        product                                  G3
  S06 partitive division  group size unknown (sharing)             G3
  S07 quotative division  group count, remainder, round up         G3-4
  S08 multiplicative cmp  "3 times as many", "a third as many"     G3-4
  S09 rates and money     price x quantity, change from a note     G3-4
  S10 multi-step mixed    2-3 operations across S01-S09            G4
  Distractor and context are rotated inside every slice (about 20
  contexts: shop, bakery, farm, school, sport, zoo, library, bus, party,
  garden, camping, music, art, pets, games, market, kitchen, beach,
  museum, toys); balance is checked after writing, not trusted.

SOURCES (training only; revised 2026-10-04: we need ~10x v1's 16k examples)
  A. seeded  agents rework the 1,310 human seeds (ASDiv + MAWPS, see HUMAN
             SETS): new wording, context, names, plus a solve(); "source"
             keeps the seed id
  B. memory  writes from scratch per slice, given 5-10 seeds as style refs
     online  searches the web for openly licensed problems of its slice,
             writes adapted items (never verbatim), records the URL
  Then two expansion layers on every kept item:
  - reword   an agent rewrites it 2-3 ways, same solve() (wording variety)
  - renumber a script redraws the numbers, re-runs solve(), keeps valid
             ones: integer, 0..999, exact division (arithmetic variety)
  Targets: ~15k written -> ~10k kept -> ~30k after reword -> ~100k after
  renumber, ~200k turns. v1 was 260 templates for 500k problems; this is
  ~30k wordings for ~100k. Renumbered copies are attached after dedup
  (numbers normalise to N, so dedup would see them as one problem).
  Pilot first [step 4]: 1 slice x 2 sources x 50 items to measure yield,
  duplicate rate and cost, then the full run.

PRUNING (in this order; every stage logs in / out / dropped-by-reason)
  1. execute     the VALIDATION checks above
  2. normalise   lowercase, digits and number words -> N, names -> NAME
                 (name list + capitalised mid-sentence words), strip
                 punctuation; "Mia has 7 apples." -> "NAME has N apples"
  3. exact       identical normalised text -> keep the first
  4. near-dup    word-sequence ratio > 0.8 against any kept item -> drop
                 ("80% the same words in the same order", difflib on the
                 normalised words). One word swapped in a 17-word problem
                 0.94, two swapped 0.83, reordered 0.39, reworded 0.34.
                 Changed 2026-10-04 from trigram Jaccard > 0.8, which let a
                 one-word swap through (0.68). Candidates come from shared
                 rare words (prefix filtering, exact: matches brute force)
  5. test leak   against any of the 1,000 SVAMP problems: sequence ratio
                 > 0.8, or trigram Jaccard > 0.5 (stricter on purpose)
  6. shape cap   shape = the operations in solve(), in the order computed,
                 follow-ups after "|", e.g. "add>mul|sub". Inside each slice no
                 full shape above 25% of the slice; the excess is dropped most-
                 redundant first (highest nearest-neighbour sequence ratio).
                 Changed after the pilot from a global 8% cap on the problem
                 shape, which would have cut most one-step subtraction (S01-S04
                 all share it; SVAMP is 77% one-step)
  Counts at each stage go to items/build_log.json — the report reads that.

SPLITS
  train          the rest
  test           10% of items, random, stratified by slice
  heldout_shape  2-3 whole shapes never trained on, chosen after step 4
                 from shapes with >= 100 items (compositional test).
                 CHOSEN 2026-10-05: add>mul (182 items), sub>div (123), sub>add
                 (109) = 414 items, 3.3%. Their parts and reverse orders stay in
                 training (mul>add 247, add>div 177, add>sub 149). Not chosen:
                 add>sub>div (S07's round-up idiom) and div>mod (remainders).
                 Follow-up turns of other items can still chain these operations
                 across turns; only the single-turn composition is unseen.
  real           746 SVAMP problems, human-written only (see HUMAN SETS).
                 Never trained on, never shown to a writer; single turn.
  Synthetic test and held-out shapes are cut by family BEFORE reword and
  renumber: every copy of a test item stays in test.

HUMAN SETS (built 2026-10-04: python -m library.domain.math_tutor.benchmarks)
  Range filter: 1-3 operations, whole non-negative numbers all the way,
  numbers <= 99, answer <= 999, grade <= 4; the dataset's equation becomes
  solve() and must reproduce the dataset's answer.
             downloaded  in range  role
  SVAMP           1,000       746  test (MIT)
  ASDiv           2,305     1,159  seeds (CC BY-NC 4.0)
  MAWPS           1,921     1,449  seeds (MIT, SVAMP repo copy)
  Seeds dedup (ASDiv first, same rules as PRUNING): 2,608 -> 1,310 (1,067
  ASDiv, 243 MAWPS). Dropped 768 exact duplicates after normalisation, 442
  near-duplicates, 88 too close to SVAMP. The human sets are partly
  templated themselves: 657 MAWPS problems are ASDiv ones with new names
  and numbers.
  Test: 577 one-step, 169 two-step; 322 pure subtraction, 45 pure
  multiplication, so accuracy is reported per shape.
  Seeds: 915 / 346 / 49 at 1 / 2 / 3 steps; grade 1-4 where labelled.

TURNS (what the teacher and the student see)
  An item with k follow-ups becomes k+1 records. Earlier turns carry the
  correct answers, the state the harness would hold:
    Problem: Mia bakes 4 trays of 6 muffins. How many muffins is that?
    Answer: 24
    Follow-up: She sells 9 of them. How many are left?
  No scaffold (v1 handed over A=? B=? C=A+B=?). The teacher is told the
  output format, the student sees only the text plus the delimiter.
  Output, candidate A (lean):  "24 - 9 = 15\nAnswer: 15;"
  Output, candidate B:         "Answer: 15;"
  A gives the student working lines and the harness something to check;
  picked on Gemma 4's accuracy and format adherence on 50 items [step 5].
  Stop token ";". Inputs <= 256 tokens, outputs <= 64.

METRICS
  task accuracy     final answer == executed answer, per turn and overall
  line validity     share of outputs whose every "a op b = c" line is true
                    (candidate A only)
  by slice, by shape, held-out shapes, real benchmark; plus the usual
  fidelity metrics (overlap, mean target rank) from the eval pass.

AGENTIC MATH TUTOR v1 (agreed 2026-10-05)
  Names (user, 2026-10-06): FOLLOW-UP TASK = a new sub-task (-> <solution>); FOLLOW-UP
  QUESTION = a question about the working (-> <explanation>). GOLD solution = derived from
  the executed solve(), correct by construction; TEACHER solution = what Gemma writes freely.
  The tutor is an agent: the distilled student plus a harness. Turn types:
    route    newest message -> first output token <solution> or <explanation>
    solve    clean history + <message> -> <solution> named steps + Answer </solution>
    explain  history + open thread + <message> -> <explanation> free text </explanation>
  History: past turns typed (<task>/<solution> main line, <question>/<explanation> side
  thread). When a message routes to <solution>, the side thread leaves the model's context
  (the harness keeps the full transcript). A thread open + a new task: route with the
  thread visible, then solve from the clean history (two-phase, one extra token-step).
  Annotation formats (annotations.py, rendered from the executed solve() trace):
    answer "Answer: 5" · working "13 - 8 = 5" · named "money left = 13 - 8 = 5" ·
    code "money_left = left - cost" (the harness runs it: program-of-thought tool use).
  Named/code labels are the writers' variable names (9,763 distinct, 2.3% generic);
  rewordings reuse the original's names, so they need a relabel pass first.
  Teacher data per format: generated (Gemma writes it) or teacher-forced (Gemma scores the
  gold text in one forward pass: correct targets + soft labels). Explanations: teacher only.
  Flags: answer_correct, route_correct. Routing test: ~100 hand-written messages.

PROVENANCE (for the thesis)
  Inputs written by Claude agents, answers computed by executing the
  agents' code, outputs and logits from Gemma 4 12B. Same split as TinyGSM
  (arXiv 2312.09241: GPT-3.5 wrote problems and Python solutions). Real
  benchmarks are only a style reference and the held-out test.

FOLLOW-UP MESSAGES: TEMPLATE PUPIL v1 (2026-10-07)
  The pupil's follow-up messages come from a template bank (questions/bank/, 3,461 templates
  from 10 writer agents, 1,842 niche), filled from what the shown solution offers (foci: step,
  fact, answer, distractor, computed mistake, what-if with the code re-run, none). Gemma only
  replies. Routes: explanation | solution (what-if = a new calculation) | out_of_scope (the
  harness answers with a fixed sentence; the message never enters the context). Engine is
  domain-free (library/agent/question_templates.py). Free-written naturalness set: 360.
  v2 wish list (raised by most writers):
    - story type, money/time per TURN and per number, not per conversation
    - {unit} ("$", "minutes"); number roles (group size / number of groups / total / change)
    - which operand came from the line before or an earlier answer ({carried})
    - a "first of several steps" feature; spelled step counts ("both", "all three")
    - {line} (the whole solution line) and noun-phrase labels: bare labels ("left", "each") read badly
    - past-tense wrong_phrase; which slip (1 or 10); distractor added vs taken away
    - the implied word ({implied_word}: week, pair, dozen); rounded_down for dropped remainders
    - what the last explanation covered (follow-ups can only be generic today)
  Writers need their own scratch folders (a shared one let batch files overwrite each other).
  Out of scope (decided 2026-10-07): wellbeing / safety messages ("someone pushed me") get no special
  handling; a real product would flag them. Stated as a limitation in the thesis.

DATA RULES UPDATED 2026-10-08 (code review fixes; corpus rebuilt the same day)
  - Held out: an item is held out if ANY turn's own shape is a held-out shape (was: turn 0 only).
  - Family = the human seed's id for items written from a seed (siblings share a split); otherwise
    the item id. Rewordings and copies keep their original's family.
  - Renumbering keeps fixed-value numbers (banknotes / coins, clock hours, ordinals, legs / wheels /
    sides) and only the number half of compounds ("thirteen-dollar").
  - SVAMP real test: problems with a written number above 99 are dropped (746 -> 735).
  - Answer-only paraphrase test (user decision): test rewordings and their copies get no labels,
    threads or teacher data; they are scored on final answers only (corpus_answer_only_test.jsonl).
  - Held-out evaluation scores per turn shape (340 held-out items have an ordinary first turn).
