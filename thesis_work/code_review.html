Adversarial code review

Five reviewers (2026-10-07/08), each assigned one area, tried to disprove every finding with small CPU tests before reporting it. No code was changed. Full evidence and scripts: agents/agentN.txt and agents/work/.

TL;DR
  • Critical, for part 1 (X-C1): the reddit students learned only the class prior. 93-100% of their predictions are the most common label, and their accuracy (best 0.621-0.630, final 0.598-0.620) sits at or below the majority baseline of 0.626. Math accuracy comes from true/false questions (numeric answers 5/284). So the reddit/math task-accuracy results, including the F-E1 'null' and the data plateau, are floor effects, not evidence. The post-gen token-level results are a separate question.
  • The code itself has no critical bugs. The core maths is right: KD loss, teacher-forced alignment, forced scoring with left padding, bf16 storage, the interpreter's safety, and the harness state machine (300 adversarial sessions).
  • The data-plateau test set also changed with the data size (T-H1 / X-H1).
  • The data pipeline would silently lose data at scale: half of the explanations (A-H1), a quarter of remainder problems (A-H2), and the train/test boundary in batches (D-M3). These must be fixed before the thin slice.
  • Cheap speed wins: about 4 h of idle GPU from rebuilt stop strings (D-H1) and evaluation that takes 64-74% of training time (T-M3).
  • Leakage to state honestly or fix: follow-up turns with held-out shapes are in train (I-H1), and siblings of the same human seed are split across train and test (I-M3).
