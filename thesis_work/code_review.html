Adversarial code review

Five reviewers (2026-10-07/08), each assigned one area, tried to disprove every finding with small CPU tests before reporting it. No code was changed. Full evidence and scripts: agents/agentN.txt and agents/work/.

TL;DR
  • No critical bugs. The core maths is right: KD loss, teacher-forced alignment, forced scoring with left padding, bf16 storage, the interpreter's safety, and the harness state machine (300 adversarial sessions).
  • One published part-1 result is weakened: the data-plateau numbers used a test set that changed with the data size (T-H1). E-01 and the vocabulary sweep are not affected.
  • The data pipeline would silently lose data at scale: half of the explanations (A-H1), a quarter of remainder problems (A-H2), and the train/test boundary in batches (D-M3). These must be fixed before the thin slice.
  • Cheap speed wins: about 4 h of idle GPU from rebuilt stop strings (D-H1) and evaluation that takes 64-74% of training time (T-M3).
  • Leakage to state honestly or fix: follow-up turns with held-out shapes are in train (I-H1), and siblings of the same human seed are split across train and test (I-M3).

The tooling and experiments review is still running; it will be added here.

high I-H1 Held-out shapes are checked on turn 0 only prune.py:215

Evidence: 1,189 training turns (328 items + 861 copies) are follow-ups whose own single-turn shape is held out (add>mul 233, sub>add 68, sub>div 27), e.g. S01-mem-b01-0082 follow-up state['now'] - 20 + 5. Contradicts domain_specs ('only the single-turn composition is unseen').

Fix: Treat an item as held out if ANY turn shape is held out (or drop those follow-ups) and rebuild.

Data generation (13)

high D-H1 Stop strings are rebuilt on every generate() call model_handler.py:203-209, :268-272

Evidence: transformers builds a new StopStringCriteria each call and the cache never hits (Gemma 4 get_vocab order varies): 0.8-1.8 s per call, about 4 h of idle GPU over the full math_tutor job; the harness, thread and label passes pay it too.

Fix: Build one StopStringCriteria per handler and pass stopping_criteria; one-token stops via eos_token_id.
