Scope of this file
------------------

- This is a planning artifact, not the final thesis text.
- The immediate goal is to compile the current argument clearly before deeper codebase analysis.
- The eventual thesis update should remain neutral, precise, and evidence driven.
- No padding should be added: every section should either explain a research decision, document an implementation mechanism, present a measured result, or state a limitation/future-work item.

Large thesis arcs
-----------------

- Reframe the project as a modifiable multi-domain distillation pipeline.
  - The central object of the thesis is not a single Reddit sentiment classifier.
  - The project should be presented as a research tool for testing domain-specific distillation across teacher models, student architectures, domains, output formats, and optimization settings.
  - Reddit sentiment classification remains an important structured-output example, but it should sit next to math word problems and Reddit post generation as evidence that the same pipeline can be adapted to different task families.
  - The thesis should emphasize that adding a domain means defining the input source, prompt, stop token, output vocabulary, generation limits, and evaluation method, rather than rewriting the whole training system.

- Present the work around three main optimization contributions.
  - Contribution 1: domain-specific input vocabulary reduction.
  - Contribution 2: domain-specific output vocabulary reduction under distillation constraints.
  - Contribution 3: a parameterizable distillation training pipeline that supports KL/CE loss annealing and temperature annealing.
  - These should be phrased as underexplored combinations rather than absolute novelty claims. The safer academic claim is that the thesis studies a practical combination of task-specific input vocabulary reduction, task-specific output projection reduction, and annealed distillation for small autoregressive students.

- Explain why input vocabulary reduction matters.
  - Many useful domains only require a small subset of a large tokenizer's input space.
  - English Reddit comments, structured classification JSON, generated math word problems, and short post-generation prompts do not need the entire Gemma tokenizer vocabulary during student inference.
  - The input embedding parameter count is linear in vocabulary size: input_embedding_params = input_vocab_size * hidden_dim.
  - For small student models this can dominate the parameter budget, causing much of the model to be spent on tokens the domain will never use.
  - The practical deployment story should be explicit: if a local reduced-vocabulary student receives an unsupported token, the system can reject the request, normalize/preprocess it, or route it to a larger model. This makes the optimization compatible with real systems rather than assuming perfect inputs.
  - Current implementation note: the reduced-input model path currently raises an error on unseen token IDs. Routing, normalization, or UNK fallback should be described as deployment strategies or future engineering unless implemented before final thesis submission.

- Add concrete parameter calculations for vocabulary reduction.
  - The thesis should include transparent formulas and at least one worked example.
  - General formula:
    total_params ~= input_vocab_size * h + output_vocab_size * h + output_vocab_size + 16 * L * h^2 + norm_params
  - For h=48, L=3, full Gemma-sized input and output vocabularies:
    input = 262,144 * 48 = 12,582,912
    output = 262,144 * 48 + 262,144 = 12,845,056
    transformer_body = 16 * 3 * 48^2 = 110,592
    norm ~= 336
    total ~= 25,538,896 parameters
  - For the reduced Reddit sentiment 48h/3L configuration:
    input = 68,328 * 48 = 3,279,744
    output = 525 * 48 + 525 = 25,725
    transformer_body = 110,592
    norm ~= 336
    total = 3,416,397 parameters
  - This is roughly 22.12M fewer parameters than the fully unoptimized 48h/3L version, or an 86.6% reduction.
  - For h=384, L=12, full Gemma-sized input and output vocabularies:
    input = 100,663,296
    output = 100,925,440
    transformer_body = 28,311,552
    norm ~= 9,600
    total ~= 229,909,888 parameters
  - For h=384, L=12 with Reddit input vocabulary and 525-token output vocabulary:
    input = 26,237,952
    output = 202,125
    transformer_body = 28,311,552
    norm ~= 9,600
    total ~= 54,761,229 parameters
  - This is roughly 175.15M fewer parameters than the fully unoptimized 384h/12L version, or a 76.2% reduction.
  - Verification needed before final thesis insertion: confirm the exact run metadata for the math 48h/3L example, because the intended "3.4M" comparison may correspond to the reduced Reddit sentiment run rather than the currently available math run metadata.

- Explain why output vocabulary reduction is powerful but trickier than input vocabulary reduction.
  - Reducing the output projection is a direct parameter win because output_projection_params = output_vocab_size * hidden_dim + output_vocab_size.
  - However, standard knowledge distillation depends on the teacher's probability distribution, not only the single correct token.
  - If the output vocabulary is reduced too aggressively, the KL divergence loss can lose much of the "soft target" information described by Hinton et al. and later distillation work already cited in the thesis.
  - The thesis should explain the design compromise: keep the valid task tokens plus whitespace, prompt-related tokens, and auxiliary tokens so the soft label remains richer than a hard label while still being much smaller than the full Gemma vocabulary.
  - For structured domains, the necessary token set can be very small, but retaining auxiliary tokens can improve the distillation signal.
  - For free-form post generation, the output vocabulary must be larger because plausible continuations are more diverse, and the distributional signal from KL becomes more important. In the current post_generation runs, the output vocabulary is 26,659 tokens, not ~525 tokens.
  - This gives the thesis a useful third regime:
    structured sentiment: 525 output tokens;
    structured math: 528 output tokens;
    freer post generation: 26,659 output tokens.
  - For h=48, full Gemma-sized output projection would be 262,144 * 48 + 262,144 = 12,845,056 parameters. The current post_generation output head is 26,659 * 48 + 26,659 = 1,306,291 parameters, saving about 11.54M output-head parameters, or 89.8% of that layer.

- Present the third contribution as the training pipeline and annealing method.
  - The pipeline supports configurable KL ratio schedules and temperature schedules.
  - The intended training logic is curriculum-like:
    first, high KL weight and high temperature encourage the student to learn the teacher's broader distribution;
    later, lower temperature and more CE pressure sharpen the model toward correct next-token prediction.
  - This should be connected to the existing thesis sources on soft targets, annealing knowledge distillation, curriculum temperature, and cosine schedules.
  - The key claim should be measured and careful: in highly structured domains the benefit of KL/CE or temperature annealing can be hard to separate from CE, because the valid next-token distribution is often sharp. In freer text generation, the mixed KL+CE plus temperature annealing result is more informative because there is meaningful competition among many plausible next tokens.

- Interpret the structured-output results carefully.
  - The provided aggregate table shows that pure CE, pure KL, and KL/CE schedules can perform similarly on smaller structured tasks.
  - This is not a failure of the technique; it is evidence that structured JSON and math outputs often have sharp token distributions.
  - In those settings, there may be only one clearly correct next token for much of the sequence, especially punctuation, braces, field names, digits, operators, and fixed scaffold text.
  - Therefore KL's extra distributional information can be smaller than expected.
  - The thesis should state that the experiments did not show a universal win for KL or annealing on all reduced-vocabulary structured tasks.
  - The important result is more nuanced: the pipeline makes such comparisons possible, and the benefit appears stronger when the generation task has a richer output distribution.

- Add the free-form Reddit post-generation experiment as the strongest evidence for annealed KL+CE plus temperature annealing.
  - Free-form post generation was the most challenging domain because the target output is less rigid than JSON or math scaffolding.
  - A smaller batch of roughly 10k comments was needed to sample frequently used tokens for the free-form output vocabulary.
  - Distillation data became much heavier: post-generation batches are about 512 MB per batch, compared with roughly 5.5 MB for math and 5.9 MB for text sentiment. This should be verified from stored data before final wording if the local batch files are not available.
  - The top-k analysis should be used to explain why the mixed method is practically strongest:
    mixed KL/CE with temperature annealing had the highest top-20 target-token accuracy;
    pure KL preserved teacher distribution shape slightly better;
    pure CE lost much more teacher-distribution overlap.
  - Current top-k result to include after verification:
    mixed KL99->50, temp 5->3: top-20 accuracy 69.08%, teacher/student top-20 overlap 34.61%, mean target rank 486.31
    pure CE, temp 1: top-20 accuracy 67.55%, overlap 26.69%, mean target rank 1068.92
    pure KL, temp 5: top-20 accuracy 64.42%, overlap 37.31%, mean target rank 464.70
  - Interpretation:
    pure KL is the strongest teacher-distribution mimic;
    pure CE is stronger than pure KL at target-token prediction but loses much of the teacher distribution;
    the mixed schedule gives the best target-token result while retaining much of the KL distributional richness.

- Add an anecdotal but clearly labeled observations section.
  - These observations should not be presented as proven conclusions unless backed by repeated experiments.
  - Starting around KL=0.99 and ending around KL=0.6 or KL=0.5 appears to preserve the benefit of KL better than the originally intended 0.9->0.1 schedule.
  - A more aggressive schedule such as 0.9->0.1 may overemphasize CE late in training and weaken the distributional work learned earlier.
  - KL and CE losses are not symmetric in scale or behavior, so the optimal mixture is sensitive to domain, output vocabulary size, temperature, and how sharp the teacher distribution is.
  - Development note for possible appendix/methodology footnote:
    KL+CE mixing was originally introduced while investigating poor generation quality caused by a tokenizer/encoding bug. After the bug was fixed, the mixed loss remained useful for principled reasons: it balances teacher-distribution following with deterministic next-token pressure.

- Add a domain section with each domain's role in the research.
  - Reddit comment sentiment classification:
    structured JSON generation with tone, sentiment, safety, and toxicity fields. This is the easiest domain to explain and demonstrates that a small autoregressive model can reproduce a teacher's structured classification behavior.
  - Math word problems:
    generated Hungarian-relevant "szoveges feladatok" style arithmetic reasoning tasks, represented as structured calculation traces. This domain tests whether the pipeline handles deterministic symbolic-ish outputs, longer contexts, digits, operators, and scaffolded reasoning.
  - Reddit post generation:
    free-form text generation from a comment to a plausible originating post. This domain is less constrained, creates much larger distillation data, and is the best current test case for whether KL distribution following matters beyond rigid structured output.

- Document the technical system as a research tool.
  - The thesis should include a concise implementation section explaining that data generation and training can be queued and left running.
  - The pipeline supports multiple domains and teacher models in configuration.
  - Training is parameterized by hidden dimension, layer count, head count, dropout, epoch count, batch size, learning rate, warmup ratio, KL start/end, temperature start/end, max training examples, train/test split, and auxiliary token percentage.
  - The system saves checkpoints, logs training/evaluation metrics, supports graceful shutdown, and stores enough run metadata for later comparison.
  - The analysis tooling should be described as an evolving research suite: inference comparison, live testing on tricky data, run comparison, scaling plots, confusion matrices, training curves, and top-k teacher/student analysis.
  - Keep this section technical and concise. It should not become a product pitch.

- Update limitations and future work.
  - The project is mostly complete as a proof-of-concept pipeline, but the research needs more experiments before making strong universal claims.
  - Future work should include more random seeds, more baselines, more teacher models, more domains, vertical scaling within a domain, horizontal scaling across domains, reduced-input ablations, reduced-output ablations, and better free-form quality metrics.
  - The thesis should explicitly state that the current results support the feasibility and usefulness of the pipeline, while broader claims require continued experimentation.

Additional findings from project survey
---------------------------------------

- The local project has substantial experimental evidence already.
  - 120 run directories are present.
  - 119 runs have completed status and final evaluation logs.
  - Domains represented in run metadata:
    reddit_comment_sentiment: 82 runs;
    math_word_problem: 30 runs;
    post_generation: 8 runs.
  - 75 runs use reduced input vocabulary and 45 runs use full input vocabulary.
  - This is strong enough to justify a "research platform and experiment registry" framing, not just a proof-of-concept script.

- The thesis should include a compact experiment inventory table.
  - Suggested columns:
    domain, experiment group, run count, parameter range, input vocabulary size, output vocabulary size, epochs, training examples, metric used.
  - This table should appear before detailed results so the reader can see what was actually measured.
  - Avoid relying on ad hoc run names alone. Run names are useful for reproducibility, but the thesis should group them by research question.

- Evaluation metrics need a glossary.
  - Teacher-forced token accuracy:
    the student receives the correct previous tokens as context. This is useful for measuring local next-token learning, but it is optimistic.
  - Student-only token accuracy:
    the student feeds its own previous predictions back into the model. This better reflects autoregressive inference.
  - Sentiment task accuracy:
    parsed JSON fields compared to the teacher output.
  - Math task accuracy:
    extracted final solution compared to the teacher output.
  - Post-generation completion rate:
    whether the output reaches `<end>`. This is a structural completion metric, not a semantic quality metric.
  - Top-k target accuracy:
    whether the teacher-generated target token appears in the student's top-k distribution under teacher-forced context.
  - Teacher/student top-k overlap:
    how much of the teacher's likely-token set is also likely under the student.
  - Mean target rank:
    average rank of the target token in the student's output distribution; lower is better.

- The sentiment scaling result should be emphasized, but interpreted carefully.
  - The completed full-input TSC scaling runs range from 5.3M to 129.2M parameters.
  - Final student-only accuracy moves from 92.55% to 93.25%.
  - Final parsed category accuracy moves from 86.00% to 87.42%.
  - This suggests strong diminishing returns for this structured task after very small models, but the thesis should not claim a universal scaling law from one domain.
  - It is also a warning that token accuracy can look saturated because much of JSON generation is fixed syntax. Parsed task accuracy and confusion/F1 are more informative for the label decisions.

- The reduced-input TSC runs are a strong thesis result.
  - Similar parameter budgets with reduced input vocabulary perform at least competitively with full-input scaling runs.
  - Examples from completed runs:
    full-input 5.3M TSC: 92.55% student, 86.00% category accuracy;
    reduced-input 4.9M TSC: 92.87% student, 86.33% category accuracy.
    full-input 10.6M TSC: 92.83% student, 86.06% category accuracy;
    reduced-input 10.1M TSC: 93.22% student, 87.20% category accuracy.
  - The strongest academic framing is not "input reduction alone caused the improvement", because the reduced-input runs also use different depth/width allocations. The safer claim is that input vocabulary reduction frees enough parameter budget to build more useful transformer bodies at similar total model sizes.

- Embedding/body ratio is an especially clear visualization.
  - Full-input 5.3M TSC run: embedding/body ratio is about 409.6x.
  - Reduced-input 4.9M TSC run: embedding/body ratio is about 8.3x.
  - Full-input 129.2M TSC run: embedding/body ratio is still about 3.6x.
  - Reduced-input 36.8M TSC run: embedding/body ratio is about 1.5x.
  - A figure or table showing this ratio may explain the optimization better than parameter totals alone.

- Math should be treated as a structured-output stress test, not yet as a reduced-input experimental win.
  - The available math runs use full Gemma input vocabulary, so their 12.7M parameters are dominated by input embeddings.
  - The architecture notes say math can be reduced to about 1,282 input tokens, which would be a very large theoretical win.
  - For h=48, L=3, math with 1,282 input tokens and 528 output tokens would be roughly:
    input = 1,282 * 48 = 61,536
    output = 528 * 48 + 528 = 25,872
    body = 110,592
    norm ~= 336
    total ~= 198,336 parameters
  - This would be about 98.4% smaller than the current full-input math 48h/3L runs, but this should be presented as a planned/derived ablation until trained.

- The post-generation experiment needs its own evaluation language.
  - Student-only token accuracy around 4-5% looks extremely low compared to structured JSON, but the output vocabulary is 26,659 tokens and the task has many plausible continuations.
  - Completion rate is not semantic correctness.
  - The top-k analysis is therefore a better fit for this domain than exact token sequence accuracy alone.
  - The mixed run's top-k win should be presented as evidence about distribution shaping and next-token ranking, not as proof that the generated posts are semantically better.

- The distillation corpus is filtered by reduced-output feasibility.
  - During data generation, examples are skipped if the teacher produces response tokens outside the allowed response token set.
  - This is a reasonable engineering constraint for reduced-output distillation, but it creates selection bias.
  - The thesis should mention that the student is trained on examples where the teacher response is representable in the reduced output vocabulary.
  - This matters especially for free-form generation, where vocabulary coverage is a central difficulty.

- The data-size story is important enough for the implementation/results boundary.
  - Storing teacher logits scales with output vocabulary size and generated sequence length.
  - This explains why post_generation batches are much larger than math or sentiment batches.
  - The thesis should connect storage cost to the output vocabulary design: increasing the output vocabulary improves soft-label richness but increases distillation data size.
  - Possible future work: store top-k logits, quantize logits, or use lower-precision storage to reduce data-generation artifacts.

- The training speed improvement deserves a named paragraph.
  - The thesis already mentions the shift from one forward pass per token to one causal forward pass per sequence.
  - This is not just an implementation detail; it changes the feasibility of the experiment.
  - Suggested framing: "Vectorized teacher-forced loss computation".
  - The point is that causal masking allows all target positions to be scored in one forward pass, while still preventing later tokens from leaking into earlier predictions.

- The "research tool" section should be grounded in concrete artifacts.
  - Queue files define runs.
  - `info.json` stores architecture, hyperparameters, status, timestamps, and parameter counts.
  - `training.jsonl` stores train batches, train epochs, eval epochs, mini-evals, and confusion matrices.
  - Checkpoints are stored per run.
  - Analysis tools can compare runs, generate plots, evaluate checkpoints, run inference, and run top-k teacher/student analysis.
  - This is enough to support reproducibility claims if the thesis explains the artifact layout clearly.

- Some older project notes are now outdated and should not be copied blindly.
  - Earlier docs describe output vocabulary reduction as the key innovation while retaining full input vocabulary. The current stronger story is both input and output vocabulary reduction.
  - Earlier docs describe the project mostly as Reddit sentiment JSON distillation. The current project has three domains.
  - Earlier docs mention 5M to 198M or 5M to 127M ranges depending on when they were written. The thesis should use values regenerated from current run metadata.
  - Earlier docs mention 31 math output tokens, but current run metadata reports 528 output tokens with auxiliary vocabulary enabled.

Commit-by-commit thesis update plan
-----------------------------------

Commit 1: Reframe the abstract and introduction.
Rewrite the abstract and opening motivation so the thesis is clearly about a configurable multi-domain distillation pipeline. Sentiment classification should remain an example, but not the whole identity of the project. The review focus should be whether the reader understands the pipeline and research question within the first page.

Commit 2: Add a contributions/positioning section.
Add a short section that names the three main contributions: input vocabulary reduction, output vocabulary reduction, and annealed distillation training. Phrase them as a practical, underexplored combination rather than unsupported novelty. The review focus should be whether each contribution is specific, testable, and later supported by data.

Commit 3: Restructure the domain descriptions.
Split the domain discussion into three clearly separated subsections: Reddit sentiment JSON, math word problems, and Reddit post generation. Each subsection should state input format, output format, stop token or termination rule, vocabulary implications, and evaluation method. The review focus should be whether the domains justify the claim that the system is configurable and multi-domain.

Commit 4: Add input vocabulary reduction theory and calculations.
Add the parameter formula and worked examples showing how full Gemma-sized embeddings dominate small student models. Include the deployment logic for unsupported tokens: reject, normalize, or route to a larger model. The review focus should be arithmetic correctness and whether the text avoids overstating the generality of the optimization.

Commit 5: Add output vocabulary reduction and KL tradeoff.
Explain that output projection reduction is a major parameter win, but reducing the output distribution too far can weaken KL-based distillation. Connect this to soft targets and dark knowledge using the existing distillation sources. The review focus should be whether the section makes clear why the project keeps auxiliary tokens instead of only the minimal valid output tokens.

Commit 6: Rewrite the training-method section around annealed KL/CE and temperature.
Describe the intended curriculum: broad teacher-distribution learning early, sharper next-token pressure later. Explain KL ratio schedules and temperature schedules together, not as unrelated knobs. The review focus should be whether the method is understandable without reading the code.

Commit 7: Insert structured-output experiment interpretation.
Add the aggregate CE/KL/KL+CE table for sentiment and math tasks, then interpret it conservatively. The key message should be that structured outputs often have sharp distributions, so KL and CE can look similar. The review focus should be whether the thesis avoids forcing a strong conclusion where the data only supports a nuanced one.

Commit 8: Add experiment registry and metric definitions.
Add a table generated from current run metadata that groups experiments by domain, run count, parameter range, vocabulary sizes, and evaluation metric. Add a short metric glossary before the results. The review focus should be whether all later result claims are traceable and whether metric names stop being overloaded across domains.

Commit 9: Add the free-form post-generation experiment.

The review focus should be whether the thesis explains why mixed KL/CE plus temperature annealing is strongest for practical generation while pure KL remains strongest at teacher-distribution mimicry.

Commit 10: Add scaling and reduced-input vocabulary results.
Add the full-input TSC scaling curve result and the reduced-input comparison. Emphasize diminishing returns on the structured task and the embedding/body ratio shift caused by input vocabulary reduction. The review focus should be whether the thesis avoids claiming a controlled ablation where architecture shape also changed.

Commit 11: Add vocabulary coverage, rejection, and data-filtering caveats.
Explain that reduced vocabulary creates a coverage boundary, that the current reduced-input code rejects unseen token IDs, and that data generation skips teacher outputs outside the allowed reduced-output token set. The review focus should be whether the deployment story is honest about what is implemented now versus what is proposed for production routing.

Commit 12: Add anecdotal observations as clearly labeled observations.

Include the tokenizer-bug origin story only if it helps explain research process or design evolution. The review focus should be that these are not presented as settled experimental conclusions.

Commit 13: Add technical system/tooling section.
Document the queueable data-generation and training workflow, parameterized run configuration, checkpointing, graceful shutdown, logs, and analysis tools. Include the vectorized causal forward-pass optimization and the storage cost of saved teacher logits. Keep it concise and reproducibility-oriented. The review focus should be whether this section supports the "research tool" claim without becoming a feature list for its own sake.

Commit 14: Update limitations and future work.
Add a limitations section that names missing baselines, limited teacher diversity, limited domain count, possible run-count weakness, and evaluation gaps for free-form generation. Add future work for more seeds, more teacher models, more domains, horizontal and vertical scaling, and better OOD routing. The review focus should be whether limitations make the thesis more credible rather than weaker.

Commit 15: Final consistency pass.
Normalize terminology across the thesis: teacher/student, student-only accuracy, teacher-forced accuracy, classification accuracy, top-k accuracy, output vocabulary, input vocabulary, KL ratio, temperature. Check all calculations, all source references, and all claims marked for verification. The review focus should be whether every paragraph earns its place.
